Translate an address

Predict first

A user passes 0xc0000000 to write(). Is it caught by is_user_vaddr or by pagedir_get_page?

By is_user_vaddr. It returns vaddr < PHYS_BASE (vaddr.h:59), and 0xc0000000 is not below itself. Note that the address IS mapped: it is physical 0, so a page-table check alone would let it through.

A user passes 0x10000000. It is below PHYS_BASE. Is it safe?

No. It is a user address, but nothing is installed there. pagedir_get_page returns NULL. You need both checks: "is it user?" and "is it mapped?".

The arguments overflow the stack page. What stops them from overwriting the code?

Distance and an empty gap. The code sits near 0x08048000, about 3 GB lower. Below 0xbffff000 nothing is mapped, so a write there page-faults. During argument passing, push also refuses to go below PHYS_BASE - PGSIZE (process.c:297).

The user stack frame sits at physical 0x00300000 (say). Name its two virtual addresses.

User: 0xbffff000 (set by install_page, process.c:733). Kernel: 0xc0300000 = ptov (0x300000). That second name is kpage, the pointer palloc_get_page returned (process.c:730).

How a process gets the kernel half

/* userprog/pagedir.c:18–21 */
uint32_t *pd = palloc_get_page (0);
if (pd != NULL)
  memcpy (pd, init_page_dir, PGSIZE);
/* Copies entries 768..1023 (0xc0000000 >> 22 = 768).
   Entries 0..767 (user half) start empty. */

How a user page gets a frame

/* userprog/process.c:730–733 (setup_stack) */
kpage = palloc_get_page (PAL_USER | PAL_ZERO);
install_page (((uint8_t *)PHYS_BASE) - PGSIZE, kpage, true);
/* kpage is the kernel name of the frame (0xc0......).
   install_page gives it a second, user name. */

Takeaways

  1. 0xc0000000 is a virtual address. It is PHYS_BASE. It maps to physical 0x00000000. The kernel half is always "virtual minus PHYS_BASE".
  2. User pages have no fixed offset. palloc_get_page (PAL_USER) hands out any free frame from the user pool. The page table records which one.
  3. Every user frame has two names. The user name (0x0804…, 0xbfff…) and the kernel name (0xc0…). The kernel can write through either.
  4. The stack starts at PHYS_BASE and grows down. Only one page is mapped (0xbffff000–0xbfffffff). Overflow hits unmapped memory and page-faults.
  5. Every process shares the same kernel half. pagedir_create copies the top directory entries. A syscall needs no CR3 switch, so the kernel can read user memory directly.
  6. Safe user pointer = two checks. Below PHYS_BASE? Then mapped in this process's page directory? B's safemem.c does both.
